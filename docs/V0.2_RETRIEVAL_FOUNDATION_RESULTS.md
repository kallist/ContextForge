## Implemented Architecture

- `contextforge-task-analysis-v2`: bounded deterministic action, mode, technical signal, concept, risk, collision, and diagnostic extraction. Raw task text remains request-scoped and untrusted.
- `contextforge-context-plan-v2`: path-free role templates and focus-signal identities used for retrieval diagnostics only. Pack V1 allocation does not consume the plan.
- `CandidateEvidenceV2`: stable evidence identity, source/family, matched task signal, relative file/symbol target, verified location, ambiguity, relationship/distance, bounded contribution, and explanation without source bodies.
- Candidate Fusion: canonical repository-relative file deduplication, stable provenance/family/symbol preservation, per-source and per-family caps, deterministic ranking, and fail-closed rejection outside the selected snapshot.
- `contextforge-retrieval-v2`: coarse family-aware priority tiers for direct identity, verified lexical/ownership, complementary structural support, and weak Git evidence.
- Lexical ownership: one tokenization pass per verified file maps matches to the unique narrowest reliable parsed symbol. Unsupported, missing, malformed, or ambiguously overlapping ranges retain file-level lexical evidence and do not fabricate an owner.
- Benchmark adapter: invokes the same `searchRepositoryV2` application use case and injects its result into unchanged Pack V1. No benchmark-only ranker exists.

No SQLite schema, generation transaction, scanner/source-reader port, repository boundary, lexical byte-hash verification, graph depth/caps, estimator, serialized budget policy, public CLI command, or MCP tool/default changed.

Causal interpretation:

- structural support accounts for the largest recall gain, with lower precision;
- ambiguity handling recovers the final file-recall step and reduces aggregate top-10 tie surplus from 26 to 23 in that ablation, without changing symbol recall;
- ownership improves overall Gold coverage but does not move required-file/symbol recall on this slice; FULL also increases tie/cap activity, so ownership/ranking still needs narrow correction;
- no combinatorial weight search, task-ID exception, or per-repository rule was used.

FULL source diagnostics across 24 tasks record 1,111 identity, 2,008 lexical, 1,144 ownership, and 18,233 bounded structural evidence items; 92 lexical-only and 32 structural-only discoveries; 477 graph promotions; 9 ambiguity-discounted signals; 1,144 ownership successes and 1,163 explicit ownership fallbacks. Three required symbols present before Pack are lost during Pack V1, which is recorded but not addressed by this retrieval-only phase.

## Security, Persistence, and Compatibility

- Repository discovery, ignore/sensitive/generated/dependency exclusion, source size/byte caps, and repository-relative identities are reused unchanged.
- Source text contributes lexical evidence only after its current hash matches the active generation. Stale bytes remain excluded and Search remains read-only.
- Evidence/diagnostics contain bounded metadata and relative identities, not source bodies, private absolute paths, or secrets.
- Task analysis executes no shell, repository source, model, or network request. No dependency or provider was added.
- SQLite schema remains version 2; no migration or writer behavior changed. Readers still use one active snapshot and concurrent activation remains generation-isolated.
- `contextforge-structural-v1`, `contextforge-pack-v1`, `contextforge-generic-v1`, public CLI Search/Pack, and MCP Search/Pack remain available and unchanged by default. `buildContextPack` gained only an internal typed Search injection seam for the benchmark-selected shared V2 application path.

## Review and Limits

Independent review found no production references to benchmark task IDs, fixture-specific ranking branches, Gold, dataset IDs, or per-repository exceptions. No V1 source ranker, public adapter, SQLite schema, benchmark Gold/dataset/reference file, graph cap, or estimator diff exists. The benchmark adapter contains no duplicate ranker.

- BLOCKING: none for the V0.2-02 foundation acceptance gate.
- IMPORTANT: the 8K stale-source task regression and unchanged symbol/document misses prevent a general V2 improvement claim and keep ADR-009 Proposed.
- MINOR: FULL ownership increases diagnostic tie/cap activity; later correction should improve provenance prioritization without raising caps or tuning frozen tasks.

Pack V2, plan-aware budget allocation, dedicated Test/Impact Linking V2, embeddings, LLM query/reranking, new schema, public V2 selector/default, Workbench, Context Capsule, and V0.3 features are **NOT IMPLEMENTED**.

The defensible next phase is a narrowly scoped retrieval/ownership correction focused on the stale-source and still-missed symbol/document classes. Broader Symbol/Test/Impact Linking should wait until that correction passes the same frozen protocol.
