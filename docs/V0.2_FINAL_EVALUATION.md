## Candidate architecture and decision

| Candidate | Pipeline | Classification | Selected |
| --- | --- | --- | --- |
| A | TaskAnalysis + identity/lexical/structural fusion + Ranking V2 + Pack V1 | ACCEPTABLE_EXPERIMENTAL | NO |
| B | A + bounded transient relationship intelligence + Pack V1 | RETAIN_FOR_RESEARCH | NO |
| C | B + packing ContextPlan + direct-context-priority-v1 + Pack V2 | ACCEPTABLE_EXPERIMENTAL | YES |

Audited source: `benchmarks/src/systems.ts::runBenchmarkSystem`, `src/application/search-repository-v2.ts::searchRepositoryV2`, `src/application/build-context-pack-v2.ts::buildContextPackV2`, and `src/composition/contextforge-application.ts::createContextForgeApplication`. A uses FULL retrieval; B/C use RELATION_FULL. C alone uses Pack V2. All use contextforge-generic-v1 version 1.0. The composition contract is V1-specific and has no strategy selector. Public exposure would require deliberate CLI/MCP request and result-contract work; this release retains internal experiments and adds no flag or hidden environment switch.

A has the strongest precision profile of A/B/C and the same or better high-budget required-file recall. B recovers useful relationship-only identities but is not generally better in aggregate; retaining the architecture does not force selecting B. C offers one additional retained required symbol at 8K and higher Overall Gold across these budgets, but loses symbol recall at 2K, file recall at 16K/32K and precision outside 8K versus B (and precision at every budget versus A). A and C trade meaningful dimensions; neither is a universal winner. No scalar final score was introduced.
