# V0.3-01R Capsule privacy correction

The initial implementation at `89ea3b662f3deacd8901559259a39b6b07746d68` exported a
POSIX absolute path after `=` in task text. Finalization withdrew READY and kept PR #11
Draft. This correction addresses free-form provenance text across Capsule and Explain;
it is not V0.3-02 and does not authorize merge or publication.

## Failure and correction

Before production edits, two real indexed V1/V2 regression tests failed with
`absolute path leaked through Capsule task metadata` (0 pass, 2 fail, 0 skip).
They first proved the raw task, Context bytes and taskHash semantics were unchanged.
The input used a synthetic home path after `path=`; no real private path was committed.

The original detector assumed a small set of leading delimiters and omitted the entire
task only when it recognized a path. More broadly, persisted free-form fields lacked
one enforced privacy policy. The correction centralizes the lexical recognizers and
fixed `<ABSOLUTE_PATH>` replacement in `src/core/capsule-privacy.ts`. Builder task/symbol/
evidence text and Explain query echoes use that policy. Protected schema text rejects
external violations without printing the offending input. Valid structured relative
paths use the established repository path validator and are preserved.

Raw task input still drives all compiler stages. `taskHash` remains SHA-256 of its exact
UTF-8 bytes. Task display is sanitized; normalized/query text is omitted if the raw task
was redacted, preventing derived username fragments from being exported. Repeated short
paths cannot expand a display beyond the existing field limit: in that case the entire
display becomes one placeholder. No plaintext backup or path-hash list is added.

The policy handles POSIX, Windows drives, UNC and local file URLs on every platform,
including punctuation-delimited occurrences and quoted spaces. Relative paths, HTTP(S)
URL tokens and ordinary slash/division forms are preserved. It is a lexical policy,
not filesystem resolution, a decoder for obfuscated text, or a general secret detector.
See the exact field classifications and limitations in [the contract](CONTEXT_CAPSULE.md).

## Regression coverage

The focused tests cover ten path examples across ten delimiter contexts, repeated and
mixed paths, quoted whitespace, file URLs, relative paths, HTTP(S), ordinary prose,
division, existing placeholders and maximum-length input. Real V1/V2 compilation checks
the original reproducer and mixed platform forms, including a long repeated-path task.
OFF/ON Markdown and manifests match, raw taskHash/payloadHash remain exact, and source
sentinels/user fragments are absent from exported Capsule and both Explain formats.

External tampering is tested in task/normalized/evidence/symbol/relationship/version/
runtime text, with a recomputed canonical hash. Structured absolute paths and invalid
diagnostic codes are rejected. Real CLI export is inspected after deleting the fixture
repository. A source-derived path-shaped symbol label is sanitized while source
selection and Context remain unchanged. Errors do not echo the synthetic private path.

The existing privacy expectation changed from whole-task null to sanitized display;
its raw-hash, derived-signal omission and leak assertions remain. Existing no-path
golden hashes did **not** change:

- V1: `8be6ef8549b7765cdb11d6bbab8286d0913f991a12793557a90bd50ea7175cb9`
- V2: `5167f0db5b5926e90fd6552969242cc1c8736e45f763fbf4d13c6c19979e5aa0`

New path-bearing fixtures assert equal outputs from two independent processes and lock:

- V1: `8bb042f565db9bb5698a49c3b0ce9aa7e3ca5a0ca027a1686ab062608affb001`
- V2: `64c656587b95086a974df7c6de4a56a4dbc326f00d8fa96d00871c3c63251016`

They run in the existing Ubuntu/Windows/macOS and minimum-Node test jobs. These hashes
are new privacy-fixture identities, not replacements for old payload/quality baselines.
Affected unsafe metadata legitimately gets a new capsuleHash; payload bytes and their
hash are unchanged. No schema-version bump or mass snapshot update was performed.

## Limits and review

Metadata commonly exceeds Context payload size; no size optimization was attempted.
This remains a later persistence/replay design input. Per-file publication is atomic,
but paired Context/Capsule publication is not a two-file transaction. Hashes identify
data, not authenticity or agent delivery. Relative filenames, symbol names and task prose
can remain private; path redaction does not make all metadata safe to publish.

The focused review covers producer sanitation, field-sensitive external validation,
query echo, expansion bounds, derived fragments, source-body absence, compiler neutrality
and scope. The final review result must also include the final conformance/performance
and hosted evidence; it must not inherit the withdrawn zero-blocker claim.

ADR-012 remains PROPOSED. Public default is V1; package version stays 0.2.0. Replay, Diff,
history, Workbench, Override and V0.3-02 are NOT IMPLEMENTED/NOT STARTED. Docker, real
coding-host consumption and agent-success impact are NOT TESTED by this correction.
PR #11 remains Draft and unmerged after successful correction; merge needs separate
authorization.
