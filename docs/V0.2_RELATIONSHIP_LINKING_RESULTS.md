## 1. Goal

Test whether bounded, high-confidence symbol, caller, implementation, and test relationships add retrieval value on top of the V0.2-02 foundation without changing Pack V1, the SQLite schema, security exclusions, or the public V1 default.

## 2. Scope

This slice adds an internal `contextforge-retrieval-v2-relations` comparison that uses the same TaskAnalysis, ContextPlan, CandidateEvidence, Candidate Fusion, Ranking V2, verified source snapshot, and Pack V1 path as V0.2-02. It adds no public CLI flag or MCP surface. It adds no dependency, database migration, network/model call, persisted source body, or source execution.

## 3. Relationship Model

`RelationshipEvidenceV2` records one directional repository-relative relationship with a stable ID, typed source and target file/symbol identities, coarse confidence, explicit classification, derivation, generation-bound provenance, optional source location, diagnostics, and fixed distance `1`. The contract rejects absolute/traversing paths and invalid fact/confidence combinations. Repeated call sites for one semantic source/type/target relationship retain the deterministic earliest provenance location and do not multiply score.

Implemented relationship types are `SYMBOL_REFERENCES_SYMBOL`, `SYMBOL_IMPLEMENTS_SYMBOL`, `TEST_REFERENCES_SYMBOL`, `TEST_IMPORTS_FILE`, `TEST_ASSOCIATED_WITH_FILE`, and `FILE_DEPENDS_ON_FILE`. Existing generation-graph import/test facts are reused and exposed through the contract; they are not persisted again or independently double-scored.

## 4. Fact vs Heuristic

- `STRUCTURAL_FACT` requires `EXACT` confidence. It covers unique parsed direct calls, uniquely resolved named/namespace imports, explicit uniquely resolved TypeScript `implements`, direct test symbol calls, and existing exact import/test graph edges.
- `HEURISTIC` cannot use `EXACT`. Existing unique-basename/mirrored-directory test associations retain `HIGH` or `MEDIUM` confidence and their original graph derivation.
- No unresolved textual call-like match becomes a relationship. Frozen full diagnostics report 1,527 visible relationships: 1,521 structural facts and 6 explicit heuristics. Heuristics produced zero relationship-only candidate discoveries.

## 5. Caller Linking

Supported caller facts are same-file unique top-level identifier calls, same-class `this`/`self` method calls, calls through one uniquely resolved named import, and calls through one uniquely resolved namespace import. The general stale-source case derives `FileSystemRepositorySourceReader.readTextFile -> readOnce` from parsed same-file syntax with exact generation/location provenance.

Dynamic receiver dispatch, reflection, function values, prototype mutation, monkey patching, ambiguous imports, duplicate symbol targets, and alias chains that cannot be resolved uniquely emit no caller edge. Partial/degraded parse results fail closed.

## 6. Interface / Implementation

TypeScript/TSX explicit `class X implements Y` is supported when `Y` is a unique same-file interface or a named import whose module and interface resolve uniquely. Reverse discovery reuses the same directional fact. JavaScript/Python type-shape or same-method-name inference is not implemented. Extends/inheritance, generics requiring compiler resolution, qualified type expressions, declaration merging, and ambiguous imports are rejected rather than guessed.

## 7. Test Linking

A parsed call from a test symbol to a uniquely resolved production symbol produces `TEST_REFERENCES_SYMBOL`. Existing graph facts distinguish direct test imports (`TEST_IMPORTS_FILE`, structural) from naming/directory association (`TEST_ASSOCIATED_WITH_FILE`, heuristic). The wording is deliberately `references`, `imports`, or `associated with`; runtime coverage is not measured and `TEST_COVERS` is not claimed.

## 8. Impact Bounds

Impact means direct nearby repository entities, not definite runtime impact. Expansion starts from at most 24 priority-tier-1/2 candidates and 24 seed symbols, parses at most 128 verified files that are seeds or actually spell a seed symbol, walks only distance `1`, accepts at most 16 relationships per seed, 8 callers, 8 tests, 8 implementations, and 256 total relationship evidence items, and keeps the existing final 256-candidate cap. Degree above 24 is damped; cap and hub events are reported. No recursive closure is performed, so cycles cannot loop.

## 9. Security

Relationship derivation receives only files admitted by the Safe Repository Map and re-read with the active generation hash. Candidate Fusion rejects targets outside that snapshot. A relation cannot reintroduce ignored, sensitive, generated-policy, dependency, symlink/junction escape, or outside-root files. The committed model persists no source body, secret, credential, task, absolute private path, or relationship row. It executes no repository code, shell, model, or network request.

## 19. Final Correctness Review — Lexical Shadowing Fix

Finalization status: **BLOCKED by the measured performance guardrail**. The scope correction is local and uncommitted; no corrected-head CI or merge is claimed. The mixed quality result is not the blocker.

### History and root cause

Initial CI passed on `adfebee91aaf629e27d8596d1ba2753de57fbf80`. The subsequent semantic merge review found a missed negative case; that green CI did not establish scope correctness. Both of these parsed examples incorrectly produced an `EXACT / STRUCTURAL_FACT` edge from `caller` to the outer `helper`:

```ts
export function helper() { return 1; }
export function caller(helper: () => number) { return helper(); }
```

```ts
export function helper() { return 1; }
export function caller() { const helper = () => 2; return helper(); }
```

`addDirectCalls` retained spelling/form/range, but no local binding information. `directCallTarget` matched the spelling to a unique top-level function/class or named import. The indexed symbol representation is not a lexical binding table: it omits parameters and local variable declarators. Existing tests covered unshadowed calls and ambiguous receivers/import targets, not nearer value bindings. The first new regression run against unchanged production code had 21 failures and 3 passing controls, including both original reproductions.

### Narrow correction

The parser adapter now builds transient local binding-name sets during one syntax traversal and walks the call's enclosing scopes. It does not resolve values, execute source, or inspect other repository files. Bare calls carry only an optional `SHADOWED`/`UNPROVEN` rejection marker into the existing relationship derivation. Rejected outer targets produce no relationship, including no heuristic substitute. Bounded count diagnostics are `RELATIONSHIP_CALL_SHADOWED` and, for unsupported binding patterns, `SHADOW_DETECTION_PARTIAL`.

The guard handles JS/TS function and arrow parameters, `const`/`let` block scope including TDZ, function-scoped `var`, local function/class/enum declarations, named function/class expressions, destructuring, catch bindings, loops, switch scopes, and nested closures. Binding collection precedes call queries, so declaration order cannot create a false outer fact. Pure type aliases/interfaces and TypeScript's explicit type-only `this` parameter do not shadow runtime names. Block-local bindings do not blacklist the entire function. Self-recursion retains the existing intentional omission of self-edges without becoming unresolved.

Python uses separate function-local rules: assignments, parameters, local definitions/imports, loop targets, exception/with aliases, and comprehensions. Class attributes are not treated as lexical enclosures of method bodies. `global`/`nonlocal`, capture patterns and other unproven cases are rejected conservatively rather than promoted to outer facts. This is partial binding safety, not complete Python/JS semantic resolution; dynamic reassignment, receiver/namespace rebinding, runtime import hooks and data-flow remain outside scope. Existing member-call resolution is unchanged: a local `helper` does not suppress `this.helper()`, `self.helper()` or `namespace.helper()`.

The guard costs one local syntax traversal plus enclosing-scope lookups per bare call; it introduces no repository-wide per-call search or persistent symbol table. Schema, generation writers, dependency versions, ranking weights/caps, Pack V1 and public defaults are unchanged. The correction is transient, so the persisted language-analysis version is not changed.

### Regression and validation evidence

The new negative regressions cover parameter/const/let/var/function/class/enum shadows, arrow parameters, destructuring/default/rest patterns, catch bindings, nested scopes, for/switch scopes, named expressions, static-block vars, and imports shadowed by parameters or locals. Positive controls cover top-level and unique imported calls, block/catch escape, unrelated nested bindings, pure type names, recursion, and existing member calls. A real index/search integration test verifies that false caller evidence cannot enter relationship output or Candidate Fusion and that repeated output is deterministic.

### Measured redundancy and narrow correction

A disposable instrumented compiled copy of C measured each Search independently. On the fixed corpus every repetition parsed **40 files**, built **40** binding indexes over **55,554 named nodes**, and made **1,191** bare-binding queries. The corresponding synthetic counts were 24 files, 24 binding indexes, 672 nodes, and zero bare-binding queries. This is per selected file per Search, not per call, symbol, seed, or relationship family. Syntax selection already runs once after bounded high-quality seed discovery; it was not changed.

Fixed-corpus instrumented component medians before optimization: native tree parse `84.660 ms`; binding collection `84.511 ms`; direct-call extraction **including** binding collection `104.396 ms`; import extraction `7.462 ms`; implements extraction `11.131 ms`; binding queries `0.764 ms`; resolved-import lookup `2.682 ms`; source-call resolution `1.775 ms`; test-call resolution `0.472 ms`; implementation-target lookup `0.073 ms`; complete symbol relationship derivation after parsing `16.338 ms`; relationship expansion `3.960 ms`. Parent/child timings overlap and medians are not additive. Source/test resolutions share one pass, rather than deriving callers again for tests.

Native parsing and syntax traversal dominate relationship overhead. The repeated linear symbol/import lookups exist, but are not dominant on these controls, so no speculative core lookup-index rewrite was made. The much larger synthetic repository selects only tiny service files, explaining why total repository file count does not predict relationship parse/traversal cost.

The narrow optimization combines call/import/implements node discovery with the existing scope-binding traversal, retaining depth-first order and extracting only the collected node lists afterward. Node type is read once per binding-visitor invocation because the installed Tree-sitter getter crosses the WASM boundary on every access. All binding sets are still complete before any bare-call query. No file, call, declaration, relationship family, confidence rule, or bound is skipped. Grammar initialization/native parsing and indexed language analysis remain unchanged.

For N named syntax nodes, C call sites, I import nodes, K class nodes, V function-scoped declarations, and nesting depth D, the relationship-family discovery changes from up to four full walks to one, followed by O(C + I + K) targeted extraction. The scope guard remains O(N + V*D + C*D), with set membership in enclosing scopes rather than a full binding scan per call. Core caller ownership/target lookup complexity is unchanged (including its existing per-call symbol/import scans); the profile does not justify replacing it here. Temporary node lists add O(C + I + K) references only until tree deletion. Scopes, node lists, and parsed source are never cached across Search invocations or generations.
