This is the original implementation's measurement record, retained without rewriting
its samples. Finalization subsequently found an absolute-path leak and withdrew READY.
The pre-merge correction and new validation are described in
[V0.3-01R privacy correction](V0.3_CAPSULE_PRIVACY_CORRECTION.md). Final corrected-HEAD
CI/performance results belong to that correction's PR handoff, not this older run.

Base: `5741d72791c1c8fb2fa3fb6faa223fa0257f02fc`, synchronized main and v0.2.0
release lineage. Public default remains V1; package remains 0.2.0. No publication,
merge or later V0.3 phase is part of this implementation.

## Observational conformance

The frozen dataset and five budgets are unchanged. The evaluation invokes the real
Application/Core paths with Capsule OFF and ON, comparing Search, Pack manifest,
selected symbols/ranges, exact Markdown and the existing quality metric evaluator.
It repeats every ON case and compares canonical deterministic cores and both hashes.

- 240/240 paired outcomes identical: 120 V1 and 120 selected internal V2.
- 238 successful Context/Capsule pairs; two existing V1 `BUDGET_TOO_SMALL` outcomes
  remain failures with the same code/message. No payload or Capsule is fabricated for
  a failed compilation. Therefore this is **not 240 successfully emitted Capsules**.
- Selected explanation completeness: 2,771/2,771; dropped: 3,349/3,349.
- Aggregate identity: `bc0429b0c9a583e202c762935a5d8ab35619e05374fa58a24c988abef760602f`.
- Evidence: [conformance records](../benchmarks/analysis/v0.3/capsule-conformance.json).

## Size and bounds

Compact JSON bytes, across 238 emitted Capsules:

| Minimum | Median | p95 | Maximum |
|---:|---:|---:|---:|
| 25,182 | 153,532 | 1,574,281 | 1,720,125 |

Maximum observed: 65 candidate envelopes, 3,407 evidence records, 128 combined decision
and packing events, 19 selected items and 62 drops. The API uses existing candidate
limits; it does not enumerate ignored repository entries. Referenced entities use
96-bit SHA-256 ID prefixes, while source, payload and Capsule hashes retain 256 bits.

Metadata is bounded and source-free, but **is not generally smaller than the Context
payload**. The preferred size goal is not demonstrated. Explain's 8 MiB input ceiling
provides headroom without permitting unbounded input. Serialized sizes include small
runtime measurements and can vary by a few bytes; those fields do not affect identity.

Golden hashes are asserted by ordinary `npm test`, including the existing three-OS CI

Tests verify independent payload SHA-256, source sentinel absence, generation changes,
runtime exclusion, canonical keys/numbers, malformed/unsupported JSON, broken references,
duplicate IDs, unsafe paths, invalid range/order, source-stale exclusion, no speculation
for absent candidates, CLI output identity, exclusive sidecars and offline Explain after

The drop-cap regression uses more than 32 actual V1 candidates and verifies the existing
public drop presentation cap remains unchanged while Capsule records every disposition.
Score evidence preserves individual contribution multiplicity and validates its sum.

## Performance

Windows x64, Node 24.20.0; five repetitions after one warm pair, alternating OFF/ON
order. Timings cover the Application compilation, including Capsule assembly and
canonicalization/hash. They exclude optional filesystem export and CLI startup.
Offline Explain timings include validation plus representative summary/WHY queries.

| Corpus/system | OFF ms | ON ms | Ratio | Assembly ms | Hash ms | Explain ms |
|---|---:|---:|---:|---:|---:|---:|
| Fixed V1 | 901.40 | 904.60 | 1.004 | 45.20 | 23.75 | 50.97 |
| Fixed V2 | 1,277.17 | 1,374.43 | 1.076 | 89.41 | 46.51 | 70.73 |
| Synthetic V1 | 3,550.84 | 3,575.54 | 1.007 | 8.58 | 5.70 | 15.49 |
| Synthetic V2 | 3,546.73 | 3,597.95 | 1.014 | 12.60 | 7.89 | 20.20 |

The fixed corpus is the existing pinned ContextForge performance task at 8K. The
synthetic corpus reproduces the existing 1,000-file service/dependency fixture.
Both fixed-corpus systems pass the <=1.20x gate. Medians of different stages do not
add up to the median paired delta; host/runtime variation is visible in samples.
These results do not imply a speed improvement or a cross-platform performance SLA.
See [all performance samples](../benchmarks/analysis/v0.3/capsule-performance.json).

## Review and scope

The review examined compiler neutrality, evidence integrity, serialization order,
source/absolute-path leakage, hostile JSON, output publication failure, index generation
consistency and frozen algorithm boundaries. Corrections included pre-presentation-cap
drop/relationship observations, source-limit versus file-cap classification, duplicate
score contributions, and pre-schema denial-of-service bounds.

The immutable V0.2 evidence inventory is unchanged. The release check still hashes current
frozen algorithms, schemas, Gold and artifacts. Six application/adapter files with allowed
observational changes are verified against their recorded V0.2 evaluation commit. The
gate additionally requires the current full 720 case objects to equal historical results;
CI also executes Capsule conformance. No quality expected results are replaced.

MCP Capsule exposure, Replay, history/store, Diff, Gold Context Coverage, Workbench,
Human Override, V0.4 and LLM explanation are NOT IMPLEMENTED. Agent success, real coding
host consumption and Docker are NOT TESTED by this phase. Runtime Git identity refers to
the indexed safe-file snapshot; it does not claim whole-working-tree cleanliness.
