# ContextForge: the context control loop

Machine proposes. Human controls. ContextForge compiles.

V0.3 adds a local lifecycle around the existing deterministic compiler. It records
what was selected, explains captured decisions, retains metadata, verifies whether
current sources reproduce a compilation, and compares human-directed alternatives.
The public default is **contextforge-v1**. V2 is still internal/experimental with
mixed benchmark evidence. This release is not a coding agent or a PR reviewer.

## Start locally

From a source checkout, `npm run demo` creates a disposable synthetic ledger fixture
and starts the same local product server. Compile the default task at 2000 tokens,
inspect a dropped file, PIN it, recompile, compare and verify. This is a 30–90 second
demonstration; Ctrl+C removes the temporary demo repository and its local history.

With Node `>=24.15 <25` and the CLI installed:

```sh
contextforge studio --repository ./your-repository
```

Open the private URL printed by the CLI. Studio binds only `127.0.0.1`; its random
capability is in the URL fragment, never a server query log. The browser removes
the fragment and retains the capability in session storage for reload. No account,
cloud service, external font, analytics, telemetry or model API is used. Ctrl+C stops
the server. An explicit `--port` is optional; the default chooses a free port.

1. Enter a task and token budget. **Compile & save** optionally refreshes the index.
2. Inspect a file in Proposal. Explain shows recorded decisions, ranges, symbols and
   bounded evidence with their structural/heuristic/source-verification origin.
3. Read **Exact context**, **Coverage & lint**, and the compiler identity details.
4. PIN a dropped candidate or EXCLUDE an unwanted one, then **Recompile & compare**.
5. Inspect the new Capsule's semantic transitions. The prior Capsule is immutable.
6. **Verify replay** checks current sources and recompiles the recorded input.
7. Reload or restart Studio and open history. Source context is reconstructed only
   by a successful verification against current sources, not from saved source bytes.

The browser inherits a saved Capsule's controls. **Clear controls** explicitly
resets them. A new raw task is a new compilation; it is not a modification of an
old task identity. If metadata was redacted, enter the exact original task in the
Replay field before verification or control recompilation.

## CLI workflow

```sh
contextforge index ./repo
contextforge pack "fix ledger retries" ./repo --budget 2000 --capsule a.json --out a.md
contextforge explain a.json --query WHY_SELECTED --subject src/ledger.ts
contextforge history save a.json --store ./repo/.contextforge/history
contextforge history list --store ./repo/.contextforge/history
contextforge replay a.json
contextforge replay a.json --verify --repository ./repo
contextforge coverage a.json --json
contextforge recompile a.json --repository ./repo --controls controls.json --budget 3000 --out b.md > result.json
```

Example `controls.json` (a complete replacement control set, not a patch):

```json
[
  { "kind": "PIN", "path": "test/ledger.test.ts" },
  { "kind": "EXCLUDE", "path": "src/ledger-report.ts" }
]
```

Recompile saves the new Capsule and emits `{capsule, coverage, diff}` as JSON. Its
hash can be used with `history show`, `replay`, `coverage`, or `diff` and `--store`.
Use `history show <id> > b.json` to export only the new Capsule, then
`contextforge diff a.json b.json`. All emitted JSON contracts include a version.
Exact context export requires `--out`; it refuses an existing output file.

`history show/delete <id>` requires a complete 64-character Capsule hash.
`history list --limit 30 --offset 0` reads summaries only. `history prune --keep 50`
explicitly removes all but the latest 50 saved entries. Deletion is logical, not
secure erasure of database pages, journal remnants or backups. Free SQLite pages
are reused; no recursive filesystem deletion or shared-object garbage collector runs.

## What each control means

| Control | Deterministic meaning | Conflict/limitation |
|---|---|---|
| PIN | Reserve at least a useful generation-verified representation before optional allocation | Fails if source is unsafe/unavailable or minimum total output cannot fit |
| EXCLUDE | Remove a machine candidate from allocation; record LOWER_PRIORITY plus HUMAN_CONTROL provenance | Cannot exclude root instructions; conflicts with another control on the same file |
| PREFER | Allocate this eligible candidate ahead of other optional candidates, preserving original machine rank/score | Preference is not guaranteed complete-file inclusion |
| FOCUS | Apply that allocation preference to candidates at/below a normalized relative path | No extra retrieval or arbitrary filesystem read |
| RANGE | Require exactly one inclusive verified line interval for that candidate | Out-of-file range or insufficient budget is a typed conflict |

Controls apply only to the current bounded V1 proposal and cannot read ignored
files, escape the root, include stale source or weaken the final serialized token
estimate limit. Unavailable targets fail rather than silently expanding retrieval.
RANGE records `HUMAN_RANGE`; no lexical evidence is invented. PIN does not promise
the whole file. Existing root-instruction handling remains mandatory. V2 controls
are explicitly unsupported, including through its internal application entrypoint.

The source/generation is checked before recompilation and the returned generation
must still match the parent. New history is saved only after validated compilation.
The compiler still performs its normal source verification and final budget check.

## Replay semantics

| Status | Meaning |
|---|---|
| INSPECTED | Offline recorded metadata and Explain; no repository verification |
| EXACT_MATCH | Recompiled payload hash and complete deterministic Capsule hash both match |
| PAYLOAD_MATCH_PROVENANCE_CHANGED | Exact context bytes match, deterministic provenance differs |
| TASK_REQUIRED | Display text cannot recover the recorded raw task hash; supply the original |
| TASK_MISMATCH | Supplied raw task hash differs |
| SOURCE_CHANGED | At least one recorded safe source hash is missing, unsafe, changed or outside verification bounds |
| STRATEGY_UNAVAILABLE | Recorded strategy/configuration or requested controlled compiler is unavailable |
| PAYLOAD_CHANGED | Recompilation produced different bytes; recorded sources alone did not determine them |
| CANNOT_REPRODUCE | Repository/index or compilation is unavailable; offline inspection remains valid |

Verification does not mutate or refresh the index. Explicitly reindexing increments
generation, which can change the rendered payload even if file bytes are identical.
Default V1 and the maintained default Pack V2 path can be verified; other experimental
configurations are not silently substituted. Strategy configuration is compared.

**Not exact historical artifact restoration:** history has no source archive. Git
commit and filtered dirty/generation data are observations, not a globally unique
repository identity. An identical copy of the recorded safe files may reproduce
the result. Unrecorded repository state can still change retrieval or output.
Hashes detect integrity changes; they do not authenticate an artifact's author.

## Semantic Diff and coverage

`contextforge-diff-v1` compares task, repository/generation, strategy, budget,
controls, payload and Capsule identities. Stable candidate identities anchor
added/removed candidates and changes in rank/score, disposition, source hash,
symbols, selected ranges, roles, evidence, relationships, tokens and drop reasons.
Identical Capsule comparison is empty. Structured facts show associations and
recorded reasons; Diff does not claim causal inference about model behavior.

`contextforge-coverage-v1` reports selected/dropped/excluded captured candidates,
captured evidence referenced by selection, recorded planner roles and budget loss.
V1 has no experimental plan, so its role availability is not fabricated. There is
no completeness score or runtime test-coverage claim. Gold is evaluator-only.

The small lint system has no arbitrary percentage thresholds:

- `AVAILABLE_ROLE_NOT_SELECTED` (INFO): recorded plan opportunity > 0, selection 0.
- `TOP_CANDIDATE_BUDGET_LOSS` (WARNING): the rank-1 candidate has a budget-drop decision.
- `SOURCE_UNAVAILABLE` (WARNING): recorded source safety exclusions exist.

Each lint contains stable code, severity, entity identities, evidence references and
an explanation. No warning means only that these rules did not fire. Replay status
is separate and is never implied by offline coverage.

## Storage, privacy and failure boundaries

The separate history schema 1 uses `capsules.sqlite` inside `.contextforge/history`
by default. The compiler index remains schema 2 and is untouched by history writes.
Each row contains a validated gzip-compressed Capsule and indexed small summary.
Capsule SHA-256 is the primary key; saving the same deterministic identity keeps the
first stored runtime metadata. Full rows are validated on read, including bounded
decompression, structural references and identity. Summaries do not load full bodies.

SQLite transactions, WAL and synchronous FULL give atomic/recoverable saves.
Concurrent identical saves deduplicate under an immediate transaction. Failure is
explicit; corrupted duplicates are not silently repaired. Future history versions
fail before migrations or mutations. Roots/ancestors/SQLite sidecars reject symlinks,
junctions and non-regular files; database hardlinks are rejected. This is a local
trusted-user store, not isolation against an attacker controlling the same OS user
and racing ancestor replacement or altering arbitrary SQLite schema.

Bounds: 8 MiB Capsule JSON, 32 controls, one RANGE per file, 2,000 saved entries or
256 MiB compressed bodies, 100 summaries/query, 32 MiB source verification per
replay, four ephemeral Studio payloads of at most 8 MiB each, one active Studio API
operation, 16 connections, 15-second request timeout and bounded request bodies.
Storage is capped; delete/prune is explicit. Network filesystems are untested.

Raw tasks still go unchanged to the compiler and SHA-256 task identity. Capsule
display text is path-sanitized. Metadata/history contain no duplicated source bodies
or saved raw tasks. Studio never exports application root paths, stack traces or
raw index objects; dynamic UI text uses DOM text nodes, not HTML interpolation.
The server validates Host, Origin, Fetch Metadata and a per-process capability for
API calls, serves only three named static assets and has no arbitrary file API.

Exact payloads may themselves contain user/source absolute paths. Studio refuses
to return such a payload through its protected API rather than silently rewriting
its bytes. The explicit CLI `pack --out` source-output boundary still supports it.
Studio indicates that limitation; metadata, Replay, Diff and controls remain usable.
Path redaction is a lexical privacy policy, not a general secret detector. Review
repository content and generated context before forwarding it to another system.

## Evidence and limitations

Run `npm test`, `npm run studio:e2e`, `npm run package:smoke`, and the release gates.
Set `CONTEXTFORGE_STUDIO_BROWSER=1` for installed-package browser coverage. The same
package smoke supports `--public-registry` only after actual publication.
`node scripts/lifecycle-performance.mjs` records a bounded synthetic storage and
workflow measurement in ignored `.studio-output/`. Timing is environment-specific.

MCP's four existing tools remain compatible: status, index, search, pack. Lifecycle
tools are exposed by CLI and Studio; no remote MCP transport is added. JavaScript
internals are not a stable package export API. Docker, third-party agent-host UX,
millions of historical entries, network filesystems and coding-agent success are
not established by these tests. **AGENT SUCCESS NOT MEASURED. V0.4 NOT STARTED.**
