# Review the change with the context that matters

A diff shows changed lines. ContextForge Review collects supported surrounding
context under an explicit token budget: direct references, dependents, related
tests, documentation and interface/implementation relationships. It records why
context was proposed, selected or dropped. Humans and external agents review the
code; ContextForge does not approve changes or predict production failures.

## Terminal workflow

```sh
contextforge review ./repo --base HEAD --budget 8000 --refresh-index \
  --capsule review.json --out review.md
contextforge explain review.json --query SUMMARY
contextforge coverage review.json
contextforge history save review.json --store ./repo/.contextforge/history
contextforge replay review.json --verify --repository ./repo
contextforge studio --repository ./repo
```

`--base main` means main's resolved commit compared with the current tracked
working tree. It does not calculate a merge base. Stage added files first. Git
operations used by Review are read-only; the explicit index refresh writes only
the existing local ContextForge index. Output files are exclusive and never
silently overwritten. JSON output is metadata; Markdown explicitly contains source.

## Review Workspace

For a reproducible source-checkout demo, run `npm ci && npm run review:demo`.
It creates an isolated temporary Git repository, edits ledger behavior, and saves
a 1K Review Capsule with real dropped callers. Open its private Studio URL, PIN a
dropped caller from Context proposal, recompile, inspect Diff, and verify Replay.
Ctrl+C closes Studio and removes the temporary fixture. The same journey is tested
by `npm run review:e2e`, including the installed-package variant.

Enter a base and budget, then **Build Review Context**. Select a changed file to
inspect syntax-level symbol changes and before/after range coordinates. The impact
inspector distinguishes structural facts from heuristic associations. Follow a
candidate to **Context proposal** for recorded decisions, source ranges and controls.

PIN, EXCLUDE, PREFER, FOCUS and RANGE work over the bounded safe proposal. Use
**Recompile & compare** to save a new immutable Capsule, then inspect selection
transitions and verify Replay. The original remains available in history. Exact
source payloads are ephemeral; stored history contains metadata only. Existing
coding-task compilation remains available below the Review composer.

The current range display is structural, not a full side-by-side source diff.
Deleted files have metadata only. Their historical source and removed symbols are
not recovered. Unsupported, binary or security-excluded current paths cannot
bypass discovery because Git reports a change. Dynamic dispatch, plugin loading,
compiler-complete resolution and transitive runtime effects are not covered.

## Coverage and lint

Coverage reports captured changed files selected, current changed symbols fully
represented by selected ranges, and available/selected neighboring paths by
relationship type. It is not a review-completeness score. Lints carry stable codes,
severity, affected entities and recorded evidence:

| Code | Severity | Meaning |
| --- | --- | --- |
| CHANGED_SYMBOL_NOT_REPRESENTED | WARNING | A captured current symbol is not fully retained |
| DIRECT_IMPACT_NOT_SELECTED | INFO | Captured neighboring context was not selected |
| RELATED_TEST_NOT_SELECTED | INFO | A captured test relationship was not retained |
| REVIEW_CONTEXT_BUDGET_PRESSURE | INFO | Recorded candidates were dropped for budget |
| HISTORICAL_SOURCE_UNAVAILABLE | INFO | Deleted source has metadata only |

The budget includes the complete final Markdown under `contextforge-generic-v1`.
It is a token estimate, not a guarantee for every provider tokenizer. Controls
cannot bypass this limit; an impossible required representation returns a conflict.

## Compatibility and replay

Review uses Capsule v2; ordinary compilation continues to emit v1. This release
reads both. Older releases reject v2 explicitly. Index/history database schemas
are unchanged. MCP remains status/index/search/pack with the normal V1 compiler.

Replay inspects metadata offline or verifies current safe sources and recompiles
the recorded base. Missing commits, changed sources, changed HEAD/change identity,
or unavailable strategies produce a mismatch/unavailable result. No historical
source archive exists. Capsule hashes detect identity changes, not authorship.

Limits: 64 changed files, one graph hop, 100 candidates, 1,024 impact relationships,
2,048 ranges per file, 16 MiB verified current sources, bounded Git commands.
Submodule contents are not traversed; configured clean/process filters are disabled.
Candidate/relationship truncation is diagnosed. The UI bounds visible large lists;
the Capsule retains the full captured bounded metadata.

**CODING/REVIEW AGENT SUCCESS NOT MEASURED.** Structural scenario results do not
prove better reviews, bug detection, review speed or sound whole-program impact.
