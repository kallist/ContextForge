# Studio visual review

Reviewed actual Chromium 153 screenshots on Windows, not design mockups. Local captures: 1280×800, 1512×982 and 1920×1080; additional automated viewport 1024×768. Full-page screenshots are taller than the viewport by design. Public launch images are captured at 1512×982 from the synthetic session fixture.

Observed and corrected: the initial result page devoted too much height to the composer; the final result state collapses its heading and reduces the input height. The empty state retains the full question and peer Task / Current Git Change choices. Why now adds plain-language recorded reasons and keeps exact codes in a disclosure. Selected candidates precede dropped ones while retaining recorded rank numbers.

Final review: readable contrast, clear single accent, aligned budget/selection summary, wrapping paths, explicit Include control, visible dropped test, readable exact source and no overlay collision. Primary navigation is Context / Why / History; full-width evidence is subordinate to the result summary. History states that it stores metadata rather than source archives. Long candidate lists scroll vertically; controls stay in the normal flow. No animation is needed to interpret a state.

Real browser checks cover no horizontal overflow at all four required desktop sizes, primary build-control bounds, keyboard focus, five human controls, Task/Review, Exact Context, Why/Coverage, Diff, Replay, history, reload and restart. The focus test enters keyboard modality before checking focus-visible; it does not treat mouse-only programmatic focus as keyboard navigation.

The static site was separately checked at 390, 1024, 1280, 1512 and 1920 pixels, with loaded images, no overflow and zero remote runtime requests. These are local Chromium observations; no claim of cross-browser or screen-reader certification.
