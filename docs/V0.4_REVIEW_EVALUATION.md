# Review Context evaluation v1

The frozen definition is `benchmarks/review-v1.json`; the fixture generator is
`scripts/review-fixture.mjs`. Run `npm run build && npm run review:benchmark`.
Recorded raw results, source identities and local timings are in
[`REVIEW_EVALUATION_V1.json`](REVIEW_EVALUATION_V1.json).

Three synthetic Git repositories/scenarios cover TypeScript callers/tests,
TypeScript interface implementations and Python callers at budgets 1,000 and
3,000. Each case compiles twice. Gold is not passed to production. The same author
designed the implementation and annotations; this is not external independent Gold.

| Scenario | Budget | Static impact recall / precision | Related paths retained | Payload estimate |
| --- | ---: | --- | --- | ---: |
| Callers / tests | 1,000 | 9/9 / 9/9 | 2/9 | 823 |
| Callers / tests | 3,000 | 9/9 / 9/9 | 5/9 | 1,606 |
| Interface / implementation | 1,000 | 1/1 / 1/1 | 1/1 | 542 |
| Interface / implementation | 3,000 | 1/1 / 1/1 | 1/1 | 542 |
| Python reference | 1,000 | 1/1 / 1/1 | 1/1 | 522 |
| Python reference | 3,000 | 1/1 / 1/1 | 1/1 | 522 |

All six cases identified the expected changed file and symbol, remained within
budget and reproduced exact Capsule/payload identity. Local Windows total compile
times on the final hardened build were approximately 0.79–0.90 seconds, including Git commands and verification;
these tiny synthetic cases do not establish enterprise-scale performance.

## Negative evidence and limits

Caller retention remains 2/9 at 1K and 5/9 at 3K. The shared Pack V1 section policy
can leave budget unused while dropping neighboring context; the 3K case uses only
1,606 estimated tokens. The implementation was not tuned to improve this result.
The raw report preserves each dropped path. PIN provides an explicit controlled
alternative but is not used to improve benchmark scores.

A dynamic plugin path is deliberately unresolved and excluded from the static
recall denominator; no runtime completeness is implied. These narrow fixtures
contain no measured false positive, which does not prove production precision.
Large real projects, runtime dispatch, cross-platform performance and independent
human review quality are not measured here.

**CODING/REVIEW AGENT SUCCESS NOT MEASURED.** No claim of better reviews, bug
detection, reduced review time or guaranteed safe changes follows from this suite.
